## Опис проєкту
Проєкт демонструє обчислення чисел Трібоначчі рекурсивним шляхом. Досліджено три підходи:
1. Чиста рекурсія (без мемоізації).
2. Рекурсія з кешуванням підзадач (`@lru_cache`).
3. Ітеративний аналог.

## Теорія: Обмеження стеку та відсутність TCO в CPython
* **Ліміт рекурсії**: В CPython існує штучне обмеження на максимальну глибину стеку викликів (за замовчуванням близько 1000 кадрів, що перевіряється функцією `sys.getrecursionlimit()`). Якщо рекурсія йде глибше, програма падає з `RecursionError`.
* **Відсутність TCO (Tail-Call Optimization)**: На відміну від багатьох функціональних мов, CPython спеціально не оптимізує хвостову рекурсію в цикл. Отже, кожен рекурсивний виклик гарантовано створює новий кадр у стеку викликів. Тому для обробки глибоких структур завжди надійніше використовувати ітеративний підхід (через цикли `while`/`for` або власний стек `list` / чергу `deque`).

## Вплив мемоізації (`lru_cache`)
Без кешування рекурсивний підхід має експоненційну складність, оскільки постійно переобчислює одні й ті самі гілки Трібоначчі. Мемоізація зберігає результати вже вирішених підзадач у словник-кеш, перетворюючи експоненційний час обчислення на лінійний $O(n)$. Завдяки цьому час виконання `tribonacci_memoized` співмірний із `tribonacci_iterative`, хоча ліміт стеку залишається активною проблемою при великих значеннях `n`.
